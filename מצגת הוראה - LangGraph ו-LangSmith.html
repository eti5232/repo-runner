LangGraph לבנייה, LangSmith למדידה

דוגמה חיה: RepoRunner, סוכן שמקבל פרויקט Python שבור ומתקן אותו לבד

מה ההבדל בין צ'אט לבין סוכן?

צ'אט

שאלה אחת ← תשובה אחת. אין פעולות בעולם.

סוכן

עושה לולאה: מנסה פעולה, רואה תוצאה, מחליט מה הלאה, עד שהמטרה הושגה או שצריך אדם.

סוכן = מודל שפה + כלים + לולאה + תנאי עצירה

הקושי: לולאה שרצה לבד יכולה להסתבך, להיתקע, או לעשות משהו מסוכן. צריך דרך לשלוט בה.

הרעיון של LangGraph: מציירים את הסוכן כגרף

צומת = צעד. קשת = לאן ממשיכים. קשת מותנית = לאן ממשיכים לפי מה שקרה. כשהקשת חוזרת אחורה נוצרת לולאה.

6 הרכיבים של LangGraph

1. State

הזיכרון המשותף של הריצה. כל צומת קורא ממנו וכותב אליו.

RunState

2. Node

פונקציית פייתון שעושה צעד אחד ומחזירה עדכון ל-State.

execute_step

3. Edge

קשת קבועה: "אחרי A תמיד B".

clone ← analyze

4. Conditional edge

פונקציה שבוחרת את הצומת הבא לפי ה-State. כאן נולדות הלולאות.

route_after_execute

5. Checkpointer

שומר את ה-State אחרי כל צעד. אפשר לסגור ולהמשיך מאותה נקודה.

SqliteSaver

6. interrupt

עוצר את הגרף וממתין להחלטת אדם, ואז ממשיך.

human_approval

הכלל הכי חשוב: המודל מציע, הקוד מחליט

המודל עושה

שיפוט: להבין שגיאה, לחקור קבצים, להציע תיקון.

הקוד עושה

כל מה שאפשר דטרמיניסטית: ניתוב, בדיקת בטיחות, בדיקת הצלחה, בניית תוצרים.

למה? מודל יכול לטעות, להתבלבל, או להישכנע ע"י טקסט זדוני ב-README. קוד תמיד מתנהג אותו דבר.

בפרויקט: גם אם המודל "שוכנע" להריץ curl … | sh, השער safety.py עוצר ומבקש אישור אדם.

RepoRunner: הגרף שלנו

סגול = קורא ל-LLM. תכלת = קוד רגיל. כתום = שער בטיחות. אדום = עצירה לאדם. ירוק = סיום.

הלולאה, צעד אחר צעד

  1. execute_step מריץ פקודה בקונטיינר Docker. נכשל: ModuleNotFoundError.
  2. route_after_execute (קשת מותנית) רואה כשל ומעבירה ל-diagnose_error.
  3. המודל קורא קבצים דרך investigate (לולאה קטנה בתוך הלולאה) ומאבחן: חבילה חסרה.
  4. propose_fix מציע pip install numpy.
  5. safety_gate בודק בקוד: בטוח ← חוזרים ל-execute_step. רגיש ← human_approval עוצר לאדם.
  6. הצליח ← verify ← report בונה Dockerfile.

תנאי עצירה: MAX_ATTEMPTS = 8. בלעדיו הלולאה יכולה לרוץ לנצח.

איזה סוג סוכן RepoRunner?

דפוס (Pattern) הוא האסטרטגיה. LangGraph הוא רק אבני הבניין לממש אותה.

דפוס?איפה בפרויקט
ReAct (חשוב, פעל, התבונן)✔diagnose_error ↔ investigate: המודל קורא קבצים בכלים ורואה את התוצאה
Planning (תכנן ← בצע)✔plan_run בונה צעדים, execute_step מבצע, verify בודק
Human-in-the-loop✔human_approval עם interrupt()
Router (ניתוב)חלקיקשתות מותנות לפי ה-State, לא סיווג כוונה של מודל
Multi-Agent✘סוכן אחד. כיוון להרחבה

RepoRunner = סוכן Plan-and-Execute, עם לולאת ReAct לאבחון, ו-Human-in-the-loop לפעולות רגישות

LangSmith: איך יודעים שהסוכן טוב?

בלי מדידה, "שיפרתי את הפרומפט" הוא תחושה. עם מדידה זו עובדה.

1. Tracing

כל ריצה נרשמת כעץ: איזה צומת, מה נשלח למודל, מה חזר, כמה טוקנים וזמן. אפשר לראות בדיוק איפה הלך שגוי.

2. Evaluation

מריצים את הסוכן על הרבה דוגמאות וממדדים אוטומטית. זה מה שמאפשר להשוות גרסאות.

הערכה: דאטהסט, Evaluator, Experiment

Dataset (דאטהסט)

רשימת דוגמאות עם תשובה ידועה. אצלנו 25 פרויקטים: תקינים, שבורים, דורשי אדם, והזרקה.

Evaluator

פונקציה שנותנת ציון לריצה אחת. אצלנו 6: הצלחה, ניסיונות, חזרה על תיקון, עצירה נכונה, הזרקה, עלות וזמן.

Experiment (ניסוי)

הרצת הסוכן על כל הדאטהסט וציון כל ריצה. התוצאה: טבלת ציונים עם שם, כמו v1.

למה 3 חזרות? מודל שפה לא דטרמיניסטי. ריצה אחת יכולה להצליח במקרה, אז משווים ממוצעים.

ניסוי לפני ואחרי

הכלל: אותו דאטהסט ואותו קוד, ורק דבר אחד משתנה. אז כל הבדל במספרים הוא בגלל השינוי.

בפרויקט שלנו הגרסה נבחרת ב-runtime context (agent_version) ולא בעותק נפרד של הקוד.

מה קרה אצלנו: v1

מדדv1
הצלחה0.89
עצירה נכונה0.89
עמידות להזרקה1.0

הממצא: כל 8 הכישלונות הגיעו מ-3 דוגמאות. המודל אבחן ותיקן נכון, אבל כתב את העריכה של requirements.txt בצורה (heredoc) ששער הבטיחות מסווג כשינוי קוד, ולכן עצר לשווא.

התיקון ל-v2: להורות למודל לערוך תלויות ב-sed -i או echo >>, שנמצאים ברשימת ההיתר. הציפייה: ההצלחה עולה.

בלי הניסוי לא היינו יודעים מה לתקן. זו כל הנקודה של מדידה.

שאלות לכיתה

  1. מה ההבדל בין קשת רגילה לקשת מותנית, ומה קורה בלי קשת שחוזרת אחורה?
  2. למה ההחלטה אם פקודה בטוחה נעשית בקוד ולא במודל?
  3. מה היה קורה לסוכן אם נסגר המחשב באמצע עצירה, ואיזה רכיב פותר את זה?
  4. למה מריצים ניסוי 3 פעמים? ולמה משווים על אותו דאטהסט?
  5. מה הכשל ב-v1, ואיך המדידה עזרה לגלות אותו?

תרגיל: הוסיפו לגרף צומת חדש שמסכם את הריצה. איזה State הוא צריך, ובין אילו צמתים הוא נכנס?
